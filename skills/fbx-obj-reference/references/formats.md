# Разбор FBX и OBJ

## Быстрая инвентаризация

`inspect_scene.py` использует Python и NumPy. Записывай результаты в рабочую папку, исходник оставляй неизменным:

```powershell
python scripts/inspect_scene.py 'D:/project/model.fbx' --out 'D:/work/scene.json'
python scripts/inspect_scene.py 'D:/project/model.obj' --out 'D:/work/obj.json'
```

В полном дереве FBX могут быть десятки мегабайт чисел. Не выводи его в чат. Если нужен разбор NURBS, добавь `--nodes D:/work/fbx_nodes.json` и далее выбирай нужные узлы программно. JSON от Windows-инструментов иногда содержит BOM: читай через `utf-8-sig`.

## OBJ

- Индексы `f` относятся ко всему файлу, а не обнуляются после `o`/`g`. Положительные начинаются с 1, отрицательные отсчитываются от уже объявленных вершин. `0` недопустим.
- Учитывай `v`, `v/vt`, `v//vn`, `v/vt/vn`. Не предполагай треугольники: возможны четырёхугольники и другие полигоны. Для анализа связности триангуляция не нужна.
- Не останавливайся на следующем `o`, если задача не ограничена первым объектом.
- Связные компоненты по индексам помогают найти отдельные детали, но разрывы UV/нормалей могут дублировать позиции. Объединение близких вершин требует обоснованного допуска: оно способно склеить соседние элементы.
- Сверяй габариты, распределение высот, ориентацию и состав объектов. Имена материалов в MTL — визуальные метки, сами по себе не подтверждают материал строительной конструкции.
- Скрипт инвентаризации не загружает текстуры/MTL и не вычисляет свободные кривые/поверхности OBJ. Такие записи показывает отдельно.

## Бинарный FBX

Проверенный локальный путь — чтение дерева, а не импорт в Revit. У бинарного FBX версия записана после 23-байтовой сигнатуры; записи узлов до 7500 используют 32-битные поля, начиная с 7500 — 64-битные. Массивы бывают несжатые и zlib. Проверяй размер распакованного массива и границы записей; ASCII FBX обрабатывай другим читателем.

Ищи:

- `GlobalSettings/Properties70`: `UnitScaleFactor`, `OriginalUnitScaleFactor`, `UpAxis`, `UpAxisSign`, `FrontAxis`, `FrontAxisSign`, `CoordAxis`, `CoordAxisSign`.
- `Objects/Geometry`: тип последнего свойства; `Vertices` и `PolygonVertexIndex` у Mesh; `Points`, порядки и узловые векторы у NURBS.
- `Objects/Model/Properties70`: локальный перенос, поворот, масштаб, геометрические трансформации, pivots/pre/post rotation при наличии.
- `Connections/C`: для `OO` направление записи — дочерний ID, родительский ID. Геометрия, Model и вложенные геометрические узлы — разные объекты.

В `PolygonVertexIndex` отрицательное число завершает грань: индекс вершины равен `-value-1`. Это **другая семантика**, чем отрицательные индексы OBJ. Скрипт сообщает число граней, но не строит готовый mesh со всеми слоями материалов, UV и нормалями.

## NURBS: урок из навеса


- Порядок `k` означает степень `k-1`. Рабочий параметрический интервал для n точек: `[knots[k-1], knots[n]]`.
- Кривая с контрольными точками `(x,y,z,w)` вычисляется как `sum(N_i(t)*w_i*P_i) / sum(N_i(t)*w_i)`. Не забывай веса и корректную обработку правого конца интервала.
- Для поверхности нужны базисы по U и V и их произведение с весами. В проверенном файле порядок хранения был `reshape(nv, nu, 4)`; проверяй углы/края на другом экспорте, не считай этот порядок автоматически доказанным.
- `TrimNurbsSurface` связывает базовую поверхность, `Boundary` и кривые. В этом файле кривые границы давали UV; сначала вычислялась кривая, затем UV отображались на поверхность. Ищи все границы, включая отверстия: исходный разовый скрипт выбирал первую Boundary и не является универсальным обработчиком trimming.
- Для обычной поверхности разовый скрипт брал два края. Это хватало для этой задачи, но не восстанавливает произвольную поверхность целиком.
- Плотность 401/41/81 точка в примере — выбранные значения, не гарантированный допуск. Для новой геометрии проверяй отклонение хорды и крайних точек; уменьшай шаг до принятого допуска.
- Замкнутость, периодичность, повторные узлы, несколько trim-циклов и сложные Model-трансформации требуют отдельной поддержки. Если собственный читатель их не обрабатывает, используй поддерживающий их экспортёр/SDK или явно ограничь результат.

Результат этой стадии — вычисленная и преобразованная геометрия с источником и допусками. Семантику «колонна», «балка», материал и конструктивную схему определяй по заданию и проекту, а не по одним габаритам сетки.
