Целевая среда моста определяется Revit. Наличие нового SDK не разрешает автоматически менять target framework. Autodesk API DLL, pyRevit и конвертер DWG не распространяются в комплекте.

## Порядок для агента

1. Прочитать AGENTS.md и проверить компоненты через `install.ps1 -CheckOnly`.
2. Установить выбранные версии моста, явно указав папку моделей. Отсутствующие компоненты брать по официальным ссылкам. Для сборки нужны API-сборки установленного Revit.
3. У готового дистрибутива сверить контрольные суммы. Рабочие модели хранить вне исходников.
4. Добавить MCP-запись из `server/mcp-client.local.json` в фактический формат настроек клиента. Не перезаписывать другие подключения. Примеры JSON и Codex TOML находятся в examples.
5. Передать каталог навыков через `-SkillsPath`, затем проверить их обнаружение клиентом. Папка навыка в исходниках ещё не доказывает его установку.
6. Штатно перезапустить Revit, найти сеанс и выполнить чтение. Несохранённые окна автоматически не закрывать.

Переносимый пример — `server/config.example.json`. Установщик создаёт игнорируемый `server/config.json` с путями компьютера. DLL читает его на два уровня выше: сохраняйте расположение `server/bin/<год>/`. Сервер и мост используют общий config и state.

Манифест продукта — RevitBridge.addin; исходная разработческая надстройка не перезаписывается. Повторная установка сохраняет резервную копию собственного манифеста и отказывается заменять чужой. У документа должен оставаться один выбранный механизм записи.

`-Remove` снимает регистрацию. Зависимости, навыки и модели не удаляются. Одноимённые навыки при установке не перезаписываются; отдельный MCP-хост pyRevit не включается.
