# Координаты, привязка и геометрическая проверка

## Цепочка преобразований

Разделяй локальные координаты геометрии, трансформации FBX-сцены, замену осей/масштаба, общие координаты проекта и внутренние координаты Revit. Запиши порядок и соглашение матрицы. В Python ниже используются **строки**: `target_xy = source_xy @ R + translation`.

1. Проверь размерность на нескольких известных длинах: шаги осей, габариты, сечения. Для FBX сверь метаданные единиц с геометрией; в OBJ единицы не стандартизованы.
2. Определи вертикальную ось по модели, а не по привычке. В примере OBJ потребовал перехода `(x, y, z) -> (x, -z, y)` до поворота/переноса, а FBX уже имел Z вверх. Это свойства этих файлов, не форматов в целом.
3. Проверь `ProjectLocation`, координаты базовой точки и Transform импортированного DWG. При чтении `GeometryInstance` учитывай, в какой системе возвращена геометрия: не применяй один и тот же Transform второй раз.
4. Найди однозначные опорные точки или длинные края и выполни начальную привязку. Повторяющиеся ламели и сетка осей неоднозначны: ближайшая точка может оказаться соседним шагом.
5. Корректируй план отдельно от отметки. Не подгоняй масштаб, чтобы скрыть ошибку единиц; не допускай отражение без явного геометрического основания.

## Поворот и перенос по парам точек

`fit_plan_transform.py` принимает JSON с массивами `source` и `target`, минимум три неколлинеарные пары XY, в одинаковых единицах. Например, заранее измеренные точки углов одной и той же детали:

```json
{"units":"mm","source":[[0,0],[3400,0],[0,4500]],"target":[[100,200],[3500,200],[100,4700]]}
```

```powershell
python scripts/fit_plan_transform.py anchors.json --out fit.json --max-residual 2
```

Порог `2` здесь пример в единицах входа. Выбери допуск по точности исходника и задаче. Скрипт фиксирует масштаб 1, ограничивает `det(R)=+1`, пишет RMS, максимум и ошибку каждой пары; при превышении порога завершает работу с ненулевым кодом. Он не устанавливает соответствие точек автоматически.

Проверь также точки, **не участвовавшие** в расчёте, оба края/обе зоны объекта и независимые размеры. После любой корректировки заново вычисляй ошибки. Сохраняй отдельно число использованных точек и число исключённых.

## Что нельзя принимать за доказательство

- В архивном `align_canopy.py` записанный `medianResidual` вычислен до последней SVD-коррекции и по всем ближайшим точкам. Его значение около 10,20 мм нельзя называть финальной точностью привязки или ошибкой выбранных пар. Для новой работы пересчитать метрики на финальной матрице.
- Маска близких точек 0,02 мм в том скрипте отбирала совпавшие фрагменты; она не доказывает такую точность всей модели.
- `Polygon.buffer(0)` и `simplify(...)` меняют геометрию. Сравни до/после: площадь, границы, число контуров/отверстий и наложение. Не выбрасывай части `MultiPolygon`/`GeometryCollection` молча.
- Обрезка линии по внутреннему контуру может дать несколько отрезков. Отбрасывание отрезков короче 100 мм в примере было локальной настройкой; в новом проекте согласуй с реальными деталями и `ShortCurveTolerance` Revit.

## Перед моделированием

Проверь план и вертикальный разрез: верх/низ кровли, верх/низ каркаса, высоту сечения, опирание. Для 250×50 мм отдельно зафиксируй, какая сторона вертикальная.

Данные для Revit должны явно указывать единицы, систему координат и смысл Z. Если нужно сохранить верх балки, осевая линия на этой отметке ещё не гарантирует, что верх её семейства окажется там: окончательная проверка выполняется по нативной геометрии.
